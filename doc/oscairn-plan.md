# Oscairn plan: a tonewheel organ on setBfree

This branch (`oscairn`) turns setBfree into Oscairn's organ: a CLAP instrument, "setBfree"
(`org.oscairn.setbfree`), that keeps setBfree's tonewheel generator, vibrato scanner,
percussion, overdrive, reverb and Leslie model and adds what Oscairn asks of a native
instrument, and a second plugin in the same bundle, "setBfree Leslie"
(`org.oscairn.setbfree.leslie`), the Leslie alone as an audio effect (section 6). The default
branch (`master`) tracks upstream unchanged.

## 1. Goal

A great-sounding, playable tonewheel organ that supports everything Oscairn offers an
instrument. It does **not** have to match the MODX/MONTAGE organs: Jacob plays the
reference's sample organs and does not love them, so there is no recorder and no
reference to measure against. Quality is judged by ear, with listening files Jacob can
steer (section 5), and by tests that pin behaviour once it is chosen.

Out of scope here: a plugin window (Oscairn draws editors from parameters), the JACK
application and the LV2 plugins (left building as upstream has them), Windows.

## 2. How setBfree is built

setBfree is C (one C++ file for the optional convolution reverb), built with Makefiles.

| Part | Files | What it does |
| --- | --- | --- |
| Tone generator | `src/tonegen.c` (3,600 lines) | 91 tonewheels as wave tables computed at the sample rate (harmonics, temperament gear ratios, an EQ curve over the wheels), the key → bus → wheel contact matrix with tapering, crosstalk/leakage (compartment, transformer, terminal strip, wiring), key click as randomised bus contact envelopes, percussion (2nd/3rd harmonic, soft/normal, fast/slow, the upper-manual retrigger rule), swell pedal. Renders fixed 128-sample fragments (`oscGenerateFragment`); key changes queue in a ring buffer and take effect at the next fragment. |
| Vibrato/chorus scanner | `src/vibrato.c` | The scanner: a modulated delay line, V1–V3 and C1–C3, routed per manual. Part of the tone generator. |
| Overdrive | `b_overdrive/overdrive.c` (generated by `overmaker.c`) | A biased tube-like waveshaper with 4× oversampling, input/output gain, character (feedback before/after). |
| Reverb | `b_reverb/reverb.c` | A small Schroeder reverb, mix. |
| Leslie | `b_whirl/whirl.c`, `eqcomp.c` | Horn and drum: crossover filters, rotating delay-line reflections with Doppler, acceleration/deceleration time constants, brake positions, two mics, stereo. Fixed 2,048-sample delay buffers. |
| MIDI and controls | `src/midi.c` | Channel → manual mapping (upper 1, lower 2, pedals 3), splits and transposes, and the *control functions*: every live control (drawbars, switches, Leslie speed) is a named function taking a MIDI value 0–127, bound to CCs by configuration. |
| Configuration | `src/cfgParser.c`, `cfg/*.cfg` | `key=value` settings read **before** the engine initialises (tuning, crosstalk, click, Leslie geometry, ...). Changing one means building a new engine. |
| Programs | `src/program.c`, `src/pgmParser.c`, `pgm/*.pgm` | Named registrations (drawbars, switches, splits) on MIDI program numbers; `pgm/default.pgm` has 30-odd. |
| Running state | `src/state.c` | Remembers the last value of every control function and every config line, for LV2 state. |
| Front ends | `src/main.c` (JACK), `b_synth/lv2.c` (LV2 synth), `ui/` and `b_synth/ui.c` (OpenGL UIs), `b_whirl/lv2.c` (Leslie as an LV2 effect) | Allocate an instance (`allocSynth`/`initSynth`), feed it MIDI, render fragments through preamp → reverb → whirl. |

Determinism: no runtime randomness (key click "random" lengths come from a fixed
sequence), so a render is repeatable. **One global:** `SampleRateD` in tonegen and vibrato
(upstream marks it `TODO -> non-global`); two instances at different rates in one process
would share it. The fork moves it into the tone generator (small upstreamable change).

Upstream has no test suite.

### 4.1 Per-key fades

setBfree mixes keys onto nine buses inside the tone generator; there is no per-key output.
A host choke or a volume expression on one key needs that key's contribution alone.
As built: each sound's output is scaled by the largest `amplitude()` (volume expression times
choke fade, from `sound-contexts-plugin.hpp`) of its held keys, so a key's volume expression
or choke lowers the sound only where no other key of it is louder. A choked key is also
released at once: the only key of its sound fades over 3 ms; with other keys held, its own
release (2.9 ms at every rate, from the next fragment) is the fade, silent within 6 ms. Exact per-key gain would mean scaling that
key's contact gains in the tone generator: later work if Oscairn's voice stealing makes it
audible.

## 6. The Leslie as an effect

RFC 0016 and the `oscairn/sst-effects` plan list setBfree's rotary (`b_whirl`) as the
candidate for a rotary speaker. Built in session 2 as a second CLAP plugin in `setbfree.clap`:

- **"setBfree Leslie"**, `org.oscairn.setbfree.leslie` (`oscairn/leslie.cpp`), wrapping `whirl.c`
  through the engine glue's rotor (`sbf_rotor_*` in `oscairn/engine.c`). Stereo in (summed into
  the cabinet), stereo out (horn and drum on two microphones), a MIDI note port for the mod
  wheel (≥ 64 fast, below slow, on crossing) and the sustain pedal (each press toggles slow and
  fast), both reported as parameter changes.
- Its parameters are the organ's Leslie parameters, the same names, ranges, modules
  (`Leslie`, `Leslie/Rotors`, `Leslie/Cabinet`, `Leslie/Filters`) and value text, but the
  organ's on/off switch (the host bypasses an effect), then its own Mix (session 3, decision 14):
  32 parameters, Leslie speed first. Speed and Mix are live (Mix moves over 10 ms; 0 is the
  input as it came, 1 the cabinet alone, the default; role `OSCAIRN_ROLE_MIX`); the others build
  a new rotor on the main thread, which takes over the old one's rotor angles and speeds and is
  crossfaded in over 10 ms.
- `oscairn.effect-contexts`: up to 16 contexts on one engine (one rate), each with its own rotor,
  parameters and state; contexts outlive the interface they came from. `resources` reports the
  rotors held and `tail_active`. `clap.tail` is 50 ms (measured: the output dies away 16–22 ms
  after the input), and the effect returns `CLAP_PROCESS_SLEEP` once the input has been silent
  that long. `oscairn.memory` declares a rotor (1.1 MB) per context; `oscairn.ui` puts the speed
  first, as buttons. State is text (`setbfree-leslie-2` and every value, `%.17g`, C locale).
- Real-time safe (allocation guard), any block size renders the same (`whirlRamp`, section 11),
  rates 8–384 kHz (at high rates a large cabinet shrinks to fit the 2,048-sample delay lines,
  section 11).

**How the effects suite can use it** (RFC 0016's Rotary Speaker types; `oscairn/sst-effects` is
not touched here): either (a) as an external plugin, the suite's Rotary Speaker slot naming
`org.oscairn.setbfree.leslie` and passing its parameters through by name, which keeps the suite
free of GPL code and gets effect contexts and memory declarations for free; or (b) by vendoring
`b_whirl/whirl.c`, `whirl.h`, `eqcomp.c` and the glue's `sbf_rotor_*` (GPL-2.0-or-later, which
makes that build GPL-3.0, as the sst-effects plan already notes), calling
`sbf_rotor_create(rate, "whirl.*=..." lines)`, `sbf_rotor_speed`, `sbf_rotor_follow` on a
rebuild and `sbf_rotor_process` per block. The parameter table to mirror is the organ's
`Leslie*` modules in `oscairn/params.h`. Either way the suite's types (slow, fast, brake
positions, cabinet sizes) map onto these parameters as presets.

## 9. Decisions for Jacob to confirm

Decided by Jacob (2026-11-02, and 12–14 and the vendor on 2026-11-05) are marked **decided**.

1. **Licence — decided:** keep GPL-2.0-or-later for the fork and the plugins; new files under the same.
2. **Name and ID — decided:** keep setBfree's name. The organ is "setBfree",
   `org.oscairn.setbfree` (in Oscairn's own namespace, not another author's that upstream might
   claim); the effect is "setBfree Leslie", `org.oscairn.setbfree.leslie`; the bundle is
   `setbfree.clap`; the programs' preset provider is `org.oscairn.setbfree.programs`. Vendor
   "Oscairn" (confirmed). The organ's state keeps its version line `oscairn-organ-1`, so states
   saved before the rename load.
3. **One engine per sound context:** each prepared sound is a whole organ with its own
   Leslie and reverb (its memory is measured in M1). Held keys of the old sound keep their
   Leslie spinning; the alternative, one Leslie shared by all sounds, would break the
   held-notes-keep-their-sound rule for Leslie settings.
4. **Pitch bend is ignored — decided** (organs do not bend). **Transpose — decided:** a
   parameter of ±127 semitones (Jacob's no-limit rule; setBfree's own range), as are the three
   split transposes; values saved at ±48 or less mean the same.
5. **Mod wheel switches the Leslie** (≥ 64 fast, below slow, on crossing), like a
   half-moon switch; **sustain pedal**: a parameter, default "Leslie toggle" as setBfree
   does, or "Hold notes".
6. **CC 11 expression is the swell pedal** (it also drives the overdrive, as on the real
   organ), live per channel, not saved as a parameter.
7. **Keyboard mapping — decided:** MIDI channel 1 upper, 2 lower, 3 pedals as setBfree; plus split
   points so one keyboard can play lower and pedals.
8. **Defaults — decided for now:** setBfree's defaults until Jacob picks the default sound by
   ear from the listening folder: upper 88 6000 000, lower and
   pedal drawbars all in (silent), Leslie slow, vibrato C3 but routed to neither manual,
   percussion off (third, slow, normal), overdrive off, reverb 0.1.
9. **Configuration parameters rebuild the engine — decided** (44–126 ms on the main thread,
   then a 10 ms crossfade that restarts the reverb tail and Leslie rotors).
10. **Key click — decided: fix it in the tone generator.** The attack (with its click) and the
    release are defined in time: 2.9 ms (one fragment at 44.1 kHz) at every rate, the same
    shapes. Done in session 2 as the default (`osc.envelope.rate=44100`), since it is
    bit-identical to upstream at 44.1 kHz; `osc.envelope.rate=0` gives upstream's one fragment at
    every rate (the stock gate uses it at 48 and 96 kHz). A choke with other keys held fades over
    that release, 2.9 ms at every rate.
11. **The Leslie effect — decided: build it** in this fork (section 6).
12. **The Leslie's horn at high rates — decided: fix it** (organ and effect), keeping 44.1 kHz
    bit-identical. Done in session 3 as engine change 9, `whirl.reference.rate` (default 44100):
    above it the horn's directivity and reflection filters read their history 44.1 kHz's sample
    apart (interpolated) and the delay lines keep 44.1 kHz's sample of headroom; 0 is upstream's.
    The horn now matches 44.1 kHz within 0.35 dB from 1 to 4 kHz at every rate (upstream: up to
    +1.9 dB at 4 kHz with the horn stopped at 192 kHz). Above 6 kHz it stays brighter (section 11):
    that is 44.1 kHz's own bilinear warping and the Doppler lines' linear interpolation, which
    the reference rate cannot reach. Matching those too would mean dulling high rates on
    purpose: Jacob's call, by ear (listening section 13).
13. **Leslie geometry at high rates — decided: clamp the cabinet.** Done in session 3 as engine
    change 10: where a cabinet would overrun the 2,048-sample delay lines, it shrinks (its
    reflections too) by just enough to fit. That is above about 178 kHz for the largest cabinet
    (mic 100 cm, rotors 50 cm) and above about 252 kHz for the default one; elsewhere nothing
    changes. A known difference (section 11).
14. **Dry/wet on the Leslie effect — decided: add it.** Done in session 3: Mix, the effect's last
    parameter (ID 32), role `OSCAIRN_ROLE_MIX`, default 1 (all wet, as before).
15. **Versions — decided:** the plugin's version goes up whenever its sound or memory figures
    change (Oscairn measures CPU and memory per version). setBfree 0.2.0 (session 2: click,
    release, choke, presets as sounds); setBfree Leslie 0.1.0. Session 3: setBfree 0.3.0 and
    setBfree Leslie 0.2.0 (the horn at high rates, the cabinet clamp, Mix). Session 4: setBfree
    0.4.0 (snapshots prepared beside); the Leslie unchanged at 0.2.0.
16. **Instant Performance changes — proposed (session 4), for Jacob to confirm:** offer
    `oscairn.sound-snapshots/draft-1`, so Oscairn prepares the next Performance's organ sounds
    beside the playing ones instead of loading a new instance. Each prepared sound still owns a
    whole engine (decision 3); to keep preparing fast, a new engine whose configuration (the
    configuration parameters, as setBfree configuration text) matches the last engine built for
    any slot copies that engine's tone wheels (engine change 11) instead of computing them: 2.5 ms
    instead of 42 ms at 48 kHz. Capacity stays eight. A part's snapshot is its Default and the
    sounds it prepared, all prepared beside: two for a part playing one prepared sound, as
    Oscairn saves them. After a switch the instance holds its first Default (never discarded),
    the outgoing sounds until their tails end, and the incoming ones: for such a part 1 + 2 + 2,
    leaving room for the sounds of one more switch still ringing. A context costs an engine's
    memory (2.5 MB at 48 kHz) only while prepared, so raising the capacity is cheap if
    Performances need more; with too few free, Oscairn loads the snapshot into an instance as
    before.

## 11. Known differences

From upstream setBfree, and what is unfinished.

- Key-click randomness comes from a per-instance generator, not libc `rand()`: the clicks are
  equally random but not the same ones as an upstream build's.
- Vibrato depths are the same at every rate (scaled to 48 kHz); upstream's depend on the rate.
- A key's attack and release take 2.9 ms at every rate (`osc.envelope.rate`, default 44100);
  upstream's take one 128-sample fragment. Identical at 44.1 kHz. The click envelopes are seeded
  on their own (with the fork's random numbers), so they are the same at every rate.
- `whirlRamp`: the Leslie's speeds can be moved by the caller once per fixed length (the effect
  does, per 128 samples); the organ and upstream's front ends are unchanged.
- A new engine starts at the swell level instead of gliding down from 14× (upstream bug).
- The overdrive prints nothing.
- Live controls run at setBfree's 7-bit resolution, so their defaults are the nearest steps:
  reverb mix 13/127 (0.102, upstream 0.1) and overdrive drive step 45 (3.5636, upstream
  3.5675). Other settings (Leslie motors, filters, crosstalk, click, ...) are configuration
  parameters with exact values; changing one rebuilds the sound's engine (crossfaded, 10 ms),
  which resets its reverb tail and rotor positions.
- MIDI CCs do not reach setBfree's own CC map: the mod wheel switches the Leslie, CC 11 is the
  swell, CC 64 toggles the Leslie or holds notes (parameter). Pitch bend is ignored. MIDI
  program changes are not used (Oscairn does not send them; programs are presets).
- Each sound has its own Leslie and reverb (decision 3).
- Presets: programs that set no drawbars (modifiers like "Percussion ON") and random-drawbar
  programs are not listed; per-channel transposes in programs are ignored.
- **The Leslie's horn sounds at every rate as at 44.1 kHz** (`whirl.reference.rate`, default
  44100; decision 12): above it the horn's directivity and reflection filters read their history
  44.1 kHz's sample apart and the delay lines keep 44.1 kHz's sample of headroom. Upstream's work
  on neighbouring samples, so its horn gets brighter as the rate goes up. Identical at 44.1 kHz
  and below; 0 gives upstream's (the stock gate uses it at 48 and 96 kHz). Measured with white
  noise through a stopped horn at 192 kHz against 44.1 kHz: 2 kHz +0.22 dB, 3 kHz +0.30, 4 kHz
  +0.33 (upstream +0.72, +1.31, +1.87); slow or stopped, within 0.35 dB from 1 to 4 kHz at 48,
  88.2, 96, 176.4 and 192 kHz.
- **Unfinished: above 6 kHz the horn is still brighter at high rates**: at 192 kHz, slow, 6 kHz
  +1.2 dB, 8 kHz +2.6, 11 kHz +4.8 (upstream +1.6, +3.4, +6.2); stopped, 11 kHz is +5.9 (upstream
  +5.4), and at 88.2/96 kHz stopped it is about 2 dB brighter than upstream's there. This is
  44.1 kHz's own dulling, its bilinear horn filters cramped towards 22 kHz and the Doppler lines'
  linear interpolation, which the reference rate does not reproduce (decision 12).
- Where a cabinet would overrun the Leslie's 2,048-sample delay lines it shrinks, reflections
  included, by just enough to fit (decision 13): above about 178 kHz for the largest cabinet
  (mic 100 cm, rotors 50 cm), above about 252 kHz for the default one (so at 384 kHz the default
  cabinet is about two thirds of its size). Upstream writes past the lines' end there, and the
  writes wrap round as early echoes. The effect refuses rates above 384 kHz; the organ takes up
  to 768 kHz.
- The Leslie effect: speed changes made while it sleeps (input silent past its tail) ramp when
  the input comes back; a rebuilt rotor keeps the rotors' angles and speeds but starts with
  empty delay lines (crossfaded over 10 ms).
- Unfinished: sound-quality verdicts and new presets; the device build; signing.
- Event timing is setBfree's: a key or control change takes effect at the next 128-sample
  fragment (up to 2.7 ms at 48 kHz), the same in every block size. So a choke with other keys
  held is silent up to 2.9 ms + 2.9 ms after it at 44.1 kHz (measured up to 5.3 ms).
- While a sound is silent it is not rendered, so a Leslie speed change made in silence ramps
  when the next note starts.
