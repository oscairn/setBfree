# Oscairn plan: a tonewheel organ on setBfree

This branch (`oscairn`) turns setBfree into Oscairn's organ: a CLAP instrument, "Oscairn
Organ", that keeps setBfree's tonewheel generator, vibrato scanner, percussion, overdrive,
reverb and Leslie model and adds what Oscairn asks of a native instrument. The default
branch (`master`) tracks upstream unchanged.

## 1. Goal

A great-sounding, playable tonewheel organ that supports everything Oscairn offers an
instrument. It does **not** have to match the MODX/MONTAGE organs: Jacob plays the
reference's sample organs and does not love them, so there is no recorder and no
reference to measure against. Quality is judged by ear, with listening files Jacob can
steer (section 5), and by tests that pin behaviour once it is chosen.

Out of scope here: a plugin window (Oscairn draws editors from parameters), the JACK
application and the LV2 plugins (left building as upstream has them), Windows.

## 2. How setBfree is built

setBfree is C (one C++ file for the optional convolution reverb), built with Makefiles.

| Part | Files | What it does |
| --- | --- | --- |
| Tone generator | `src/tonegen.c` (3,600 lines) | 91 tonewheels as wave tables computed at the sample rate (harmonics, temperament gear ratios, an EQ curve over the wheels), the key → bus → wheel contact matrix with tapering, crosstalk/leakage (compartment, transformer, terminal strip, wiring), key click as randomised bus contact envelopes, percussion (2nd/3rd harmonic, soft/normal, fast/slow, the upper-manual retrigger rule), swell pedal. Renders fixed 128-sample fragments (`oscGenerateFragment`); key changes queue in a ring buffer and take effect at the next fragment. |
| Vibrato/chorus scanner | `src/vibrato.c` | The scanner: a modulated delay line, V1–V3 and C1–C3, routed per manual. Part of the tone generator. |
| Overdrive | `b_overdrive/overdrive.c` (generated by `overmaker.c`) | A biased tube-like waveshaper with 4× oversampling, input/output gain, character (feedback before/after). |
| Reverb | `b_reverb/reverb.c` | A small Schroeder reverb, mix. |
| Leslie | `b_whirl/whirl.c`, `eqcomp.c` | Horn and drum: crossover filters, rotating delay-line reflections with Doppler, acceleration/deceleration time constants, brake positions, two mics, stereo. Fixed 2,048-sample delay buffers. |
| MIDI and controls | `src/midi.c` | Channel → manual mapping (upper 1, lower 2, pedals 3), splits and transposes, and the *control functions*: every live control (drawbars, switches, Leslie speed) is a named function taking a MIDI value 0–127, bound to CCs by configuration. |
| Configuration | `src/cfgParser.c`, `cfg/*.cfg` | `key=value` settings read **before** the engine initialises (tuning, crosstalk, click, Leslie geometry, ...). Changing one means building a new engine. |
| Programs | `src/program.c`, `src/pgmParser.c`, `pgm/*.pgm` | Named registrations (drawbars, switches, splits) on MIDI program numbers; `pgm/default.pgm` has 30-odd. |
| Running state | `src/state.c` | Remembers the last value of every control function and every config line, for LV2 state. |
| Front ends | `src/main.c` (JACK), `b_synth/lv2.c` (LV2 synth), `ui/` and `b_synth/ui.c` (OpenGL UIs), `b_whirl/lv2.c` (Leslie as an LV2 effect) | Allocate an instance (`allocSynth`/`initSynth`), feed it MIDI, render fragments through preamp → reverb → whirl. |

Determinism: no runtime randomness (key click "random" lengths come from a fixed
sequence), so a render is repeatable. **One global:** `SampleRateD` in tonegen and vibrato
(upstream marks it `TODO -> non-global`); two instances at different rates in one process
would share it. The fork moves it into the tone generator (small upstreamable change).

Upstream has no test suite.

## 4. Oscairn integration checklist

From Oscairn's `docs/plugin-porting.md` and `developer-guide.md` (Oscairn `f0d8f68`). Every
item gets a test in `oscairn/tests/` unless it says otherwise.

| # | Item | How | Test |
| --- | --- | --- | --- |
| 1 | CLAP build: macOS arm64, Linux ARM64, Linux x86_64 | CMake in `oscairn/` builds the engine as a static library and `oscairn-organ.clap`; CI on all three | CI jobs; Oscairn's `kick-clap-scan` lists it |
| 2 | Load checks | Factory, full interface, stereo out, one note port, params/state/audio-ports complete | `kick-clap-scan`, `oscairn-plugin-check` |
| 3 | Real-time safe `process` | All allocation in init/activate/main thread; process touches preallocated engines only; structural parameter changes rebuild an engine on the main thread and hand it over lock-free | Allocation-guard test: counts `malloc`/`calloc`/`realloc`/`free`/`new` on the audio thread during `process` across notes, every parameter, sound switches, chokes |
| 4 | Deterministic, architecture-independent state | State is text: a version line, then each prepared sound's name and every parameter value printed with `%.17g` in the C locale; the same bytes on every machine | Round trip byte-identical; a fixed state renders identically after load; golden state text checked in |
| 5 | Stable ports and params across states | Ports and parameter list are compile-time tables | Test reads info before and after loading other states |
| 6 | CLAP notes, note IDs, per-note expression, `NOTE_END` | `sound-contexts-plugin.hpp` voices; an organ "voice" is a held key in a sound; a key held twice (two note IDs) keeps sounding until both release; `NOTE_END` once the key's release fragment has rendered | Note-ID test, wildcard note-off, `NOTE_END` count |
| 7 | `NOTE_CHOKE` as a 2–5 ms fade; `CLAP_NOTE_EXPRESSION_VOLUME` | A choke or volume change on a key fades that key's contribution: per-key gain needs the tone generator's per-key contact gain, so the plugin renders choked/attenuated keys through a per-sound gain ramp (section 4.1) | Choke test (no step larger than a 3 ms fade allows), volume expression test |
| 8 | MIDI too | Note port dialects CLAP and MIDI | MIDI note test |
| 9 | Native sound contexts | Each prepared sound owns a whole engine (tone generator, scanner, overdrive, reverb, Leslie). Held keys keep their sound; a sound with keys or a ringing tail stays pinned | Switching with held keys, discard refusals, snapshot round trip, eight sounds |
| 10 | `oscairn.memory` | `estimate` from a per-rate formula (no allocation); `current` from the bytes the engines hold | Test: estimate ≥ measured allocation and within 25 % of it at every rate, per context |
| 11 | Parameter metadata | Names, module paths (`Upper/Drawbars`, `Lower/Drawbars`, `Pedal/Drawbars`, `Percussion`, `Vibrato`, `Leslie`, `Overdrive`, `Reverb`, `Output`, `Keyboard`, `Tonewheels`, ...), value text both ways, stepped/enum flags | Metadata test: unique IDs, every value text parses back |
| 12 | `oscairn.ui` hints | Drawbars sliders in one joined group per manual, switches as switches/buttons, priorities (upper drawbars first), roles (`LEVEL` on Volume) | Test of hints; seen in Oscairn's editor tests where practical |
| 13 | Presets | CLAP preset discovery inside the plugin from setBfree's `pgm/default.pgm`, loaded through preset-load | Preset test: count, load one, its drawbars arrive |
| 14 | `CLAP_PROCESS_SLEEP` | When no sound has keys or a ringing tail | Test |
| 15 | Tail and latency | `clap.tail` reports the reverb/Leslie tail; latency 0 (fragments run ahead, not behind) | Test |
| 16 | `oscairn.harmony`, transport | Not relevant to an organ: no tempo-synced parts. Recorded as not applicable | — |
| 17 | Every sample rate sounds the same | 44.1/48/88.2/96/192 kHz: tonewheel pitch, Leslie rotor speeds, vibrato rate, key click and percussion decay times measured from renders | Rate test with tolerances; listening files at each rate |
| 18 | Oscairn host tests | `oscairn-plugin-check`, `oscairn-render`, worker variants | Run from a local Oscairn build; results in section 10 |
| 19 | Pitch bend, mod wheel, expression | Organs do not bend (bend ignored; decision 4); mod wheel switches the Leslie fast/slow; CC 11 is the swell (expression) pedal, per channel | Tests |

### 4.1 Per-key fades

setBfree mixes keys onto nine buses inside the tone generator; there is no per-key output.
A host choke or a volume expression on one key needs that key's contribution alone.
First version: a choke releases the key at once (the tone generator's release envelope is
one fragment, 2.7 ms at 48 kHz, which is inside 2–5 ms) and a volume expression scales the
sound's gain only when the key is the only one sounding in that sound; otherwise it is
ignored. Exact per-key gain would mean scaling that key's contact gains in the tone
generator: noted as later work if Oscairn's voice stealing makes it audible.

## 5. Sound-quality work to steer by ear

Listening folder: `forks/measurements/listen-organ/`, a README per file saying what to
listen for. Each item is a parameter (or a parameter set) so Jacob can choose by ear and
the choice becomes a default or a preset.

| Item | What setBfree has | Work | Listening files |
| --- | --- | --- | --- |
| Tonewheel models | Wheel harmonics and an EQ curve across the wheels (`osc.eq.*`); variants in `cfg/osc-*.cfg` (bassy, middy, trebly, scoop, no crosstalk, sine/triangle/square/saw) | Expose the EQ macro and its four spline points as parameters; name the variants as a list | Same chord and drawbars with each variant |
| Key click | Attack/release click levels, burst lengths, envelope models (click, cosine, linear, shelf) | Parameters; check the burst length in milliseconds is rate-independent (it is defined against the 128-sample fragment) | Staccato single notes and chords at click levels 0, default, high |
| Leakage/crosstalk | Four crosstalk amounts and a contribution floor | Parameters | Slow chords with leakage off/default/2× |
| Percussion | Fast/slow decay times, soft/normal levels, overall gain, retrigger rule | Parameters | 2nd and 3rd harmonic, fast and slow, legato vs detached |
| Vibrato/chorus | Scanner rate and V1–V3 depths | Parameters | C3 on a sustained chord, each setting |
| Overdrive | Input/output gain, character | Parameters, plus swell (expression) driving it | Swell up on a full chord |
| Leslie | Horn/drum slow/fast RPM, acceleration/deceleration, brake positions, horn/drum filters, radius, mic distance and angle, horn level and leak, widths; `cfg/whirl-*.cfg` variants | Parameters; Leslie bypass | Slow → fast → slow ramps, each variant |
| Presets | `pgm/default.pgm` registrations | Offer them as presets; add a few named organ sounds tuned by ear | One file per preset |

Gate for this section: each change has its listening file and README and Jacob's verdict
recorded here before it becomes a default.

## 6. The Leslie as an effect

RFC 0016 and the `oscairn/sst-effects` plan list setBfree's rotary (`b_whirl`) as the
candidate for a rotary speaker. setBfree already ships it as a separate LV2 effect
(`b_whirl/lv2.c`). The way to offer it to Oscairn, without building it in the effects fork:

- In this fork, a second CLAP plugin in the same bundle, "Oscairn Rotary"
  (`org.oscairn.rotary`), wrapping `whirl.c` (and optionally the overdrive preamp), with
  the Leslie parameters of the organ under the same names, and `oscairn.effect-contexts`
  (each context owns one whirl) and `clap.tail`.
- The effects suite then refers to it as an external plugin, or vendors `b_whirl` under
  GPL-2.0-or-later (the sst-effects plan already notes this makes that build GPL-3.0).
- Not built in this round unless time allows; recorded in section 10.

## 9. Decisions for Jacob to confirm

1. **Licence:** keep GPL-2.0-or-later for the fork and the plugin; new files under the same.
2. **Name and ID:** "Oscairn Organ", `org.oscairn.organ`, vendor "Oscairn".
3. **One engine per sound context:** each prepared sound is a whole organ with its own
   Leslie and reverb (its memory is measured in M1). Held keys of the old sound keep their
   Leslie spinning; the alternative, one Leslie shared by all sounds, would break the
   held-notes-keep-their-sound rule for Leslie settings.
4. **Pitch bend is ignored** (organs do not bend). Transpose is a parameter (±24 semitones).
5. **Mod wheel switches the Leslie** (≥ 64 fast, below slow, on crossing), like a
   half-moon switch; **sustain pedal**: a parameter, default "Leslie toggle" as setBfree
   does, or "Hold notes".
6. **CC 11 expression is the swell pedal** (it also drives the overdrive, as on the real
   organ), live per channel, not saved as a parameter.
7. **Keyboard mapping:** MIDI channel 1 upper, 2 lower, 3 pedals as setBfree; plus split
   points so one keyboard can play lower and pedals.
8. **Defaults:** setBfree's defaults (drawbars 888000000 upper, Leslie slow, ...) until
   Jacob picks by ear.
